1

再計算しない場合

box.classList.remove("animate");
        box.classList.add("animate");

この2行はとても短い時間で連続して実行されます。そのためブラウザから見ると、 「結局 animate クラスは付いたまま」と判断されることがあります。

起きやすい結果

アニメーションがすでに開始済みだと見なされ、もう一度再生されないことがあります。

2

再計算する場合

box.classList.remove("animate");

        void box.offsetWidth;

        box.classList.add("animate");

`offsetWidth` を読むと、ブラウザは現在の正確な幅を返す必要があります。 そのため、保留していたスタイル変更やレイアウト変更をここで反映します。

起きやすい結果

「animate が一度外れた」状態が確定し、その後で付け直されるため、アニメーションが最初から再生されます。

ブラウザから見た違い

再計算なし

animate を外す
すぐに animate を付ける
ブラウザには変化が見えにくい

ブラウザの判断：結局 animate は付いているので、同じアニメーションを再開しない場合がある。

再計算あり

animate を外す
offsetWidth を読む
外れた状態が確定する
もう一度 animate を付ける

ブラウザの判断：一度 animate が外れ、その後に新しく付いたので、アニメーションを再生できる。

ポイント

`offsetWidth` は関数ではなく、DOM要素の幅を表すプロパティです。

`void box.offsetWidth;` の `void` は、取得した幅の値を使わずに捨てるためのものです。

実際にレイアウト再計算のきっかけになるのは、`offsetWidth` を読む操作です。

便利ですが、強制的な計算なので大量の要素に何度も使うと重くなることがあります。

まとめ

レイアウト再計算をしない場合、ブラウザはクラスの削除と追加をまとめて処理し、 「変化がなかった」と判断することがあります。レイアウト再計算を挟むと、 「一度外れた状態」が確定するため、同じCSSアニメーションを再び最初から実行しやすくなります。
